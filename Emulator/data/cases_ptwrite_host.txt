# PTWRITE (F3 [REX.W] 0F AE /4) under the BARE-HOST profile: expected-value cases (Gate 1 item P18, ledger U1712, agent
# ptwrite, 2026-10-19). The bare host enumerates Intel PT and PTWRITE (CPUID.(07H,0):EBX.INTEL_PT[25] = 1, EBX 239C27EBH;
# CPUID.(14H,0):EBX.PTWRITE[4] = 1, EBX 0000005FH, P- and E-core files), so the instruction executes. SDM 325383-093 Vol2B
# PTWRITE pp. 4-500 / 4-501: it "reads data in the source operand" (64 bits with REX.W in 64-bit mode, otherwise 32) and
# makes a PTW packet only "if TriggerEn, ContextEn, FilterEn, and PTWEn are all set to 1"; flags affected: none. Intel PT
# tracing is not modelled (IA32_RTIT_CTL.TraceEn = 0, docs/quirks.md "Intel PT tracing not modelled"), so apart from its
# faults PTWRITE changes nothing. 64-Bit Mode Exceptions: #GP(0) non-canonical, #SS(0) non-canonical SS reference, #PF,
# #AC(0) "If alignment checking is enabled and an unaligned memory reference is made while the current privilege level is
# 3", #UD "If CPUID.14H.00H:EBX.PTWRITE[4] = 0. If LOCK prefix is used. If 66H prefix is used."
#   emu-alltest --cases Emulator\data\cases_ptwrite_host.txt --host --cr0 0x40033 --expect-only                (suite ptwrite_host_p)
#   emu-alltest --cases Emulator\data\cases_ptwrite_host.txt --host --host-core E --cr0 0x40033 --expect-only  (suite ptwrite_host_e)
# CR0 40033H (the Windows CR0 of the hardware cases, AM = 1) for the #AC lines. The same instructions are #UD under --guest /
# --vm and without a profile (cases_ptwrite_guest.txt). Raw Unicorn runs at CPL0, "cpl=3" lines at CPL3. Layout: RSI =
# 30028000h (MEM + 8000h), 0x10 is never mapped.
#
