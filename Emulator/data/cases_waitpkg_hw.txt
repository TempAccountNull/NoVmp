# WAITPKG (UMONITOR / UMWAIT / TPAUSE) hardware cases (plan 1.J.55, ledger U1602, agent waitpkg, 2026-10-17).
# Own snippets only. Every line is deterministic on a CPU that has WAITPKG, whatever IA32_UMWAIT_CONTROL Windows
# programmed: EDX:EAX is a past deadline (0 or 1), so by the Operation (SDM 093 Vol2B TPAUSE p. 4-730, UMWAIT
# p. 4-743) os_deadline >= instr_deadline, deadline = instr_deadline, using_os_deadline = 0, the wait loop does not run,
# CF = 0 and AF/PF/SF/ZF/OF = 0. UMONITOR addresses are inside MEM (RSI = 30028000h) or deliberately faulting. Input
# flags carry IF (ADxh): Windows runs user code with IF = 1, so the native side always has it.
#
# 1. VMware guest (this machine; CPUID.07H.0:ECX[5] = 0, WAITPKG hidden): every line is #UD natively and in the emulator
#    (the guest profile, strict):
#      emu-alltest --cases Emulator\data\cases_waitpkg_hw.txt --cpuid Emulator\data\cpuid_i5-13600k.txt --strict --xcr0 7
#    (suite cases_waitpkg_hw; the same with --guest instead of --cpuid ...)
# 2. Bare host (CPUID.07H.0:ECX[5] = 1): the lines execute natively and in the emulator under the bare-host profile:
#      emu-alltest --cases Emulator\data\cases_waitpkg_hw.txt --host --strict --xcr0 7 --hw-cpu P
#      emu-alltest --cases Emulator\data\cases_waitpkg_hw.txt --host --host-core E --strict --xcr0 7 --hw-cpu E
#    Expected there: 0 differing. Open SDM reading checked by one line (marked below): UMONITOR's 64-bit exception list
#    says "#SS(0) If the specified segment is SS and the source register is in non-canonical form"; the emulator follows
#    U51 (a CS/DS/ES/SS override is ignored in 64-bit mode, ss:[rcx] is #GP on the i5-13600K), i.e. #GP(0).
#
